## 一、重构前的准备

### 1.1 运行全部测试

在重构之前，我们先运行全部测试：

![全部测试通过](../../images/episode5_2026-02-12_19-29-23.png)

> ⚠️ **重要提示**：现在我们的测试都是通过的，当我们进行重构或开发时，必须要保证在全部测试都通过的前提下进行。

### 1.2 什么是重构？

**重构（Refactoring）** 是在不改变代码外在行为的前提下，对代码内部结构进行调整，以提高代码的可读性、可维护性和可扩展性。

| 重构原则 | 说明 |
|---------|------|
| 不改变行为 | 重构后功能不变，测试仍然通过 |
| 小步前进 | 每次只做小的改动 |
| 测试保护 | 重构前后都运行测试 |
| 持续进行 | 重构是日常开发的一部分 |

## 二、识别代码异味

### 2.1 重复代码

我们来看下面这些代码：

```java
Question question = QuestionFactory.createQuestion();
Date lastWeek = DateUtils.addWeeks(new Date(), -1);
question.setPublishedAt(lastWeek);
questionMapper.insert(question);
```

我们在很多地方都用了类似上面的代码，但是当过几个月我们再看这段代码的时候，我们还能一眼就看出这行代码的目的吗？

### 2.2 代码问题

| 问题 | 说明 |
|------|------|
| `DateUtils.addWeeks(new Date(), -1)` 是什么意思？ | 不直观，需要思考 |
| 这段代码的目的是什么？ | 创建一个已发布的问题 |
| 能否一眼看出意图？ | 不能，需要阅读多行代码 |

### 2.3 重构目标

我们修改一下 `QuestionFactory`，让代码意图更清晰：

```java
// 重构前
Question question = QuestionFactory.createQuestion();
Date lastWeek = DateUtils.addWeeks(new Date(), -1);
question.setPublishedAt(lastWeek);

// 重构后
Question question = QuestionFactory.createPublishedQuestion();
```

## 三、优化工厂类

### 3.1 修改 QuestionFactory

```java
package com.nofirst.spring.tdd.zhihu.startup.factory;

import com.nofirst.spring.tdd.zhihu.startup.mbg.model.Question;
import org.apache.commons.lang3.time.DateUtils;

import java.util.Date;

public class QuestionFactory {

    public static Question createPublishedQuestion() {
        Date lastWeek = DateUtils.addWeeks(new Date(), -1);
        Date now = new Date();

        Question question = new Question();
        question.setUserId(1);
        question.setTitle("this is a question");
        question.setContent("this is content");
        question.setCreatedAt(now);
        question.setUpdatedAt(now);
        question.setPublishedAt(lastWeek);

        return question;
    }

    public static Question createUnpublishedQuestion() {
        Date now = new Date();

        Question question = new Question();
        question.setUserId(1);
        question.setTitle("this is a question");
        question.setContent("this is content");
        question.setCreatedAt(now);
        question.setUpdatedAt(now);
        question.setPublishedAt(null);

        return question;
    }
}
```

### 3.2 工厂方法说明

| 方法 | 返回 | 说明 |
|------|------|------|
| `createPublishedQuestion()` | 已发布问题 | `published_at` 为一周前 |
| `createUnpublishedQuestion()` | 未发布问题 | `published_at` 为 null |

### 3.3 重构优势

| 优势 | 说明 |
|------|------|
| **意图清晰** | 方法名直接表达目的 |
| **代码复用** | 避免重复代码 |
| **易于维护** | 修改逻辑只需改工厂类 |
| **测试简洁** | 测试代码更简洁 |

## 五、重构技巧

### 5.1 提炼方法（Extract Method）

将重复的代码逻辑提炼成独立的方法：

```java
// 重构前
Question question = new Question();
question.setUserId(1);
question.setTitle("this is a question");
question.setContent("this is content");
Date now = new Date();
question.setCreatedAt(now);
question.setUpdatedAt(now);
question.setPublishedAt(lastWeek);

// 重构后
Question question = QuestionFactory.createPublishedQuestion();
```

### 5.2 以意图命名

方法名应该清晰表达意图：

```java
// ❌ 不好的命名
createQuestion()  // 创建什么问题？

// ✅ 好的命名
createPublishedQuestion()    // 已发布的问题
createUnpublishedQuestion()  // 未发布的问题
```

### 5.3 保持测试通过

重构的黄金法则：

```
┌─────────────────────────────────────────────────────────┐
│                  重构安全流程                          │
│                                                         │
│  1. 运行测试（全部通过）                               │
│       ↓                                                 │
│  2. 小步重构                                            │
│       ↓                                                 │
│  3. 运行测试（仍然通过）                               │
│       ↓                                                 │
│  4. 继续重构或完成                                     │
│                                                         │
│  任何时候测试失败，立即撤销或修复                       │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 六、提交代码

最后，我们来提交代码：

```bash
$ git add .
$ git commit -m 'refactory'
```

### 提交信息规范

| 前缀 | 说明 | 示例 |
|------|------|------|
| `refactor:` | 重构代码（不改变行为） | `refactor: 优化 QuestionFactory` |
| `feat:` | 新功能 | `feat: 添加发布问题功能` |
| `fix:` | 修复 bug | `fix: 修复空指针异常` |
| `test:` | 测试相关 | `test: 添加单元测试` |
