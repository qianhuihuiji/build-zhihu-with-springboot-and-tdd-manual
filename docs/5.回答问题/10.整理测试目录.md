# 整理测试目录

为了更好的组织测试，我们将已有的测试文件调整下位置。

---

## 一、为什么要整理测试目录？

### 1.1 当前问题

随着项目功能增多，测试文件也越来越多，如果都放在同一个目录下，会导致：

| 问题 | 说明 |
|------|------|
| 文件过多 | 难以快速找到目标测试 |
| 结构混乱 | 不清楚测试的分类和组织 |
| 维护困难 | 修改功能时难以定位相关测试 |

### 1.2 整理目标

| 目标 | 说明 |
|------|------|
| 按功能模块分类 | 问题相关、回答相关分别存放 |
| 清晰的文件结构 | 一目了然的目录结构 |
| 便于维护 | 快速定位相关测试 |

---

## 二、整理步骤

### 2.1 创建新目录

在 `integration` 下新建 `answers` 和 `questions` 文件夹：

```
src/test/java/com/nofirst/spring/tdd/zhihu/startup/integration/
├── answers/          # 新建：回答相关测试
└── questions/        # 新建：问题相关测试
```

### 2.2 移动测试文件

将测试文件移动到相应目录：

| 文件 | 移动到 | 说明 |
|------|--------|------|
| `PostAnswersTest.java` | `integration/answers/` | 回答相关测试 |
| `BestAnswerTest.java` | `integration/answers/` | 最佳答案测试 |
| `ViewQuestionsTests.java` | `integration/questions/` | 问题相关测试 |

### 2.3 修改命名空间

调整文件位置后，请相应修改以上文件的命名空间（package 声明）：

**移动前：**
```java
package com.nofirst.spring.tdd.zhihu.startup.integration;
```

**移动后：**
```java
// PostAnswersTest.java
package com.nofirst.spring.tdd.zhihu.startup.integration.answers;

// ViewQuestionsTests.java
package com.nofirst.spring.tdd.zhihu.startup.integration.questions;
```

---

## 三、整理后的目录结构

### 3.1 完整结构

```
src/test/java/com/nofirst/spring/tdd/zhihu/startup/
├── integration/                    # 集成测试
│   ├── answers/                    # 回答相关测试
│   │   ├── PostAnswersTest.java    # 提交回答测试
│   │   └── BestAnswerTest.java     # 最佳答案测试
│   └── questions/                  # 问题相关测试
│       └── ViewQuestionsTests.java # 查看问题测试
├── unit/                           # 单元测试
│   ├── service/                    # Service 层测试
│   │   ├── AnswerServiceImplTest.java
│   │   └── QuestionServiceImplTest.java
│   └── policy/                     # Policy 层测试
│       ├── AnswerPolicyTest.java
│       └── QuestionPolicyTest.java
└── factory/                        # 工厂类
    ├── AnswerFactory.java
    ├── QuestionFactory.java
    └── UserFactory.java
```

### 3.2 目录说明

| 目录 | 说明 | 存放内容 |
|------|------|---------|
| `integration/answers/` | 回答集成测试 | 提交回答、最佳答案等 |
| `integration/questions/` | 问题集成测试 | 查看问题、问题列表等 |
| `unit/service/` | Service 单元测试 | Service 层业务逻辑测试 |
| `unit/policy/` | Policy 单元测试 | 权限策略测试 |
| `factory/` | 工厂类 | 测试数据工厂 |

---

## 四、运行测试

### 4.1 运行全部测试

整理完成后，运行全部测试，确保功能没有被破坏：

```bash
mvn test
```

### 4.2 预期结果

所有测试应该都通过：

```
[INFO] Tests run: XX, Failures: 0, Errors: 0, Skipped: 0
```

### 4.3 如果测试失败

如果测试失败，检查：

| 检查项 | 说明 |
|--------|------|
| 包名是否正确 | package 声明是否与目录匹配 |
| 导入是否正确 | import 语句是否需要更新 |
| 依赖是否完整 | 是否有类找不到 |

## 六、测试组织最佳实践

### 6.1 目录结构原则

| 原则 | 说明 |
|------|------|
| 按功能模块分类 | 问题、回答、评论等分别存放 |
| 按测试类型分类 | 集成测试、单元测试分开 |
| 命名清晰 | 目录和文件名表达测试内容 |

### 6.2 命名规范

```
# 集成测试
integration/
├── questions/
│   ├── ViewQuestionsTest.java      # 查看问题
│   └── CreateQuestionTest.java     # 创建问题
├── answers/
│   ├── PostAnswersTest.java        # 提交回答
│   └── BestAnswersTest.java        # 最佳答案
└── comments/
    ├── PostCommentsTest.java       # 提交评论
    └── ViewCommentsTest.java       # 查看评论

# 单元测试
unit/
├── service/
│   ├── QuestionServiceTest.java
│   └── AnswerServiceTest.java
└── policy/
    ├── QuestionPolicyTest.java
    └── AnswerPolicyTest.java
```

### 6.3 测试类命名

| 测试类型 | 命名风格 | 示例 |
|---------|---------|------|
| 集成测试 | 功能描述 + Test | `ViewQuestionsTest` |
| 单元测试 | 类名 + Test | `QuestionServiceImplTest` |
| Policy 测试 | 类名 + Test | `QuestionPolicyTest` |

## 七、总结

### 7.1 本节学习要点

| 要点 | 说明 |
|------|------|
| 目录组织 | 按功能模块组织测试文件 |
| 命名空间 | 移动文件后更新 package 声明 |
| 测试验证 | 整理后运行全部测试确保无破坏 |
| 最佳实践 | 遵循清晰的命名和组织规范 |

### 7.2 整理前后对比

| 对比项 | 整理前 | 整理后 |
|--------|--------|--------|
| 文件位置 | 都在 `integration/` 下 | 按功能分类存放 |
| 查找效率 | 需要逐个查找 | 按目录快速定位 |
| 可维护性 | 文件多难以管理 | 结构清晰易维护 |

## 附录：Maven 测试命令

```bash
# 运行全部测试
mvn test

# 运行指定测试类
mvn test -Dtest=PostAnswersTest

# 运行指定目录的测试
mvn test -Dtest="integration/answers/*Test"

# 运行单元测试
mvn test -Dtest="unit/**/*Test"

# 运行集成测试
mvn test -Dtest="integration/**/*Test"

# 跳过测试
mvn clean install -DskipTests
```
