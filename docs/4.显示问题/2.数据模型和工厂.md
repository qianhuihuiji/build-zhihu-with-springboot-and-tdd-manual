# 数据模型和工厂

上一节的测试提醒我们 `QuestionMapper`、`QuestionExample`、`Question` 都不存在。所以我们接下来的工作，就是定义 `question` 数据表，并产生对应的 ORM 映射模型。

---

## 一、创建数据表

### 1.1 创建 Flyway 迁移脚本

创建文件 *src/main/resources/db/migration/V20260205__create_table_question.sql*：

```sql
CREATE TABLE `question`
(
    `id`           int unsigned NOT NULL AUTO_INCREMENT,
    `user_id`      int          NOT NULL,
    `title`        varchar(100) NOT NULL,
    `content`      text         NOT NULL,
    `created_at`   timestamp    NOT NULL,
    `updated_at`   timestamp    NOT NULL,
    PRIMARY KEY (`id`)
) ENGINE = InnoDB
  AUTO_INCREMENT = 1;
```

### 1.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int unsigned | 主键，自增 |
| `user_id` | int | 问题创建者 ID |
| `title` | varchar(100) | 问题标题 |
| `content` | text | 问题内容 |
| `created_at` | timestamp | 创建时间 |
| `updated_at` | timestamp | 更新时间 |

### 1.3 运行迁移

运行 Maven 的 `flyway` 插件命令生成表：

```bash
mvn flyway:migrate
```

执行成功后，数据库中会创建 `question` 表。

## 二、生成 ORM 映射

### 2.1 修改 Generator 配置

修改 `generatorConfig.xml` 的配置，改为生成 `question` 表：

```xml
<table tableName="question" domainObjectName="Question">
```

## 三、新建模型工厂

重新导入缺失的类之后，我们应该立即运行测试。但是你会发现，`QuestionFactory` 类还不存在。

`xxxFactory` 类是我们为了测试方便而定义的模型工厂类，它会生产我们需要的模型对象。

### 3.1 创建工厂类

创建文件 *src/test/java/com/nofirst/spring/tdd/zhihu/startup/factory/QuestionFactory.java*：

```java
package com.nofirst.spring.tdd.zhihu.startup.factory;

import com.nofirst.spring.tdd.zhihu.startup.mbg.model.Question;
import java.util.Date;

public class QuestionFactory {

    public static Question createQuestion() {
        Date now = new Date();

        Question question = new Question();
        question.setUserId(1);
        question.setTitle("this is a question");
        question.setContent("this is content");
        question.setCreatedAt(now);
        question.setUpdatedAt(now);

        return question;
    }
}
```

### 3.2 工厂类说明

| 方法 | 说明 | 返回 |
|------|------|------|
| `createQuestion()` | 创建一个默认的 Question 对象 | Question |

### 3.3 工厂模式的优势

| 优势 | 说明 |
|------|------|
| **代码复用** | 测试代码中无需重复创建对象的逻辑 |
| **统一管理** | 修改默认值只需改工厂类 |
| **可读性** | `QuestionFactory.createQuestion()` 比 `new Question()` 更清晰 |
| **灵活性** | 可以创建多个变体方法（如 `createPublishedQuestion()`） |

## 四、创建 QuestionVo

### 4.1 为什么需要 VO？

| 对象类型 | 说明 | 用途 |
|---------|------|------|
| **DO (Domain Object)** | 数据库实体类 | 与数据库表一一对应 |
| **DTO (Data Transfer Object)** | 数据传输对象 | 服务层之间传递数据 |
| **VO (View Object)** | 视图对象 | 返回给前端的数据 |

使用 VO 的好处：
- ✅ 隐藏数据库结构
- ✅ 灵活控制返回字段
- ✅ 数据格式化（如日期格式）
- ✅ 安全性（不暴露敏感字段）

### 4.2 创建 QuestionVo

创建文件 *src/main/java/com/nofirst/spring/tdd/zhihu/startup/model/vo/QuestionVo.java*：

```java
package com.nofirst.spring.tdd.zhihu.startup.model.vo;

import lombok.Data;

@Data
public class QuestionVo {

    private Integer id;
    private Integer userId;
    private String title;
    private String content;
}
```

## 七、Flyway 版本控制

### 7.1 迁移脚本命名规范

```
V{版本号}__{描述}.sql
```

| 部分 | 说明 | 示例 |
|------|------|------|
| `V` | 版本标识 | V |
| `{版本号}` | 版本号（数字或日期） | 20260205 |
| `__` | 双下划线分隔符 | __ |
| `{描述}` | 描述性名称 | create_table_question |

### 7.2 迁移历史表

Flyway 会自动创建 `flyway_schema_history` 表记录迁移历史：

| installed_rank | version | description | type | script | checksum | installed_by | installed_on | execution_time | success |
|---------------|---------|-------------|------|--------|----------|--------------|--------------|----------------|---------|
| 1 | 20260205 | create table question | SQL | V20260205__create_table_question.sql | 1234567890 | root | 2026-02-05 | 100 | 1 |
