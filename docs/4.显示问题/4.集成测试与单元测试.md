# 集成测试与单元测试

到目前为止，我们完成了一个完整的测试用例开发。如果你仔细观察的话，你会发现，这个测试会启动一个完整的 Spring 环境，这也就意味着，整个测试的时间会非常长。当你的项目很大时，测试时间会变得非常长，TDD 开发流程也会变得非常长。

所以，现在是一个很好的时机来讨论**集成测试**和**单元测试**。

---

## 一、测试类型对比

### 1.1 集成测试

| 特点 | 说明 |
|------|------|
| **测试范围** | 测试多个组件协作的完整流程 |
| **启动环境** | 启动完整的 Spring 容器 |
| **依赖** | 使用真实的数据库（Testcontainers） |
| **速度** | 较慢 |
| **用途** | 验证端到端的功能 |

### 1.2 单元测试

| 特点 | 说明 |
|------|------|
| **测试范围** | 测试单一组件（如 Service 方法） |
| **启动环境** | 不启动 Spring 容器 |
| **依赖** | 使用 Mock 对象隔离外部依赖 |
| **速度** | 非常快 |
| **用途** | 验证业务逻辑正确性 |

### 1.3 测试金字塔

```
                    /\
                   /  \
                  /    \
                 /      \
                /────────\
               /          \
              /   端到端   \
             /──────────────\
            /                \
           /     集成测试     \
          /────────────────────\
         /                      \
        /       单元测试          \
       /──────────────────────────\
      /                            \
     /──────────────────────────────\
    
    数量多 ← → 数量少
    速度快 ← → 速度慢
    成本低 ← → 成本高
```

> 💡 **建议**：遵循测试金字塔原则，编写大量的单元测试，适量的集成测试，少量的端到端测试。

## 二、单元测试示例

### 2.1 创建单元测试

创建文件 *src/test/java/com/nofirst/spring/tdd/zhihu/startup/unit/service/QuestionServiceImplTest.java*：

```java
package com.nofirst.spring.tdd.zhihu.startup.unit.service;

import com.nofirst.spring.tdd.zhihu.startup.exception.QuestionNotExistedException;
import com.nofirst.spring.tdd.zhihu.startup.factory.QuestionFactory;
import com.nofirst.spring.tdd.zhihu.startup.mbg.mapper.QuestionMapper;
import com.nofirst.spring.tdd.zhihu.startup.mbg.model.Question;
import com.nofirst.spring.tdd.zhihu.startup.model.vo.QuestionVo;
import com.nofirst.spring.tdd.zhihu.startup.service.impl.QuestionServiceImpl;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.extension.ExtendWith;
import org.mockito.InjectMocks;
import org.mockito.Mock;
import org.mockito.junit.jupiter.MockitoExtension;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;
import static org.mockito.BDDMockito.given;

@ExtendWith(MockitoExtension.class)
class QuestionServiceImplTest {

    @InjectMocks
    private QuestionServiceImpl questionService;

    @Mock
    private QuestionMapper questionMapper;

    private Question question;

    @BeforeEach
    public void setup() {
        question = QuestionFactory.createQuestion();
    }

    @Test
    void get_existed_question_by_show_method() {
        // given
        given(questionMapper.selectByPrimaryKey(1)).willReturn(this.question);

        // when
        QuestionVo existedQuestion = questionService.show(1);

        // then
        assertThat(existedQuestion).isNotNull();
        assertThat(existedQuestion.getId()).isEqualTo(this.question.getId());
        assertThat(existedQuestion.getUserId()).isEqualTo(this.question.getUserId());
        assertThat(existedQuestion.getTitle()).isEqualTo(this.question.getTitle());
        assertThat(existedQuestion.getContent()).isEqualTo(this.question.getContent());
    }

    @Test
    void get_not_existed_question_by_show_method() {
        // given
        given(questionMapper.selectByPrimaryKey(1)).willReturn(null);

        // then
        assertThatThrownBy(() -> {
            // when
            questionService.show(1);
        }).isInstanceOf(QuestionNotExistedException.class)
                .hasMessageStartingWith("question not exist");
    }
}
```

### 2.2 代码解析

#### 类级别注解

```java
@ExtendWith(MockitoExtension.class)
class QuestionServiceImplTest {
    // ...
}
```

| 注解 | 说明 |
|------|------|
| `@ExtendWith(MockitoExtension.class)` | 启用 Mockito 扩展，自动初始化 Mock 对象 |

#### 依赖注入

```java
@InjectMocks
private QuestionServiceImpl questionService;  // 被测对象

@Mock
private QuestionMapper questionMapper;  // Mock 对象
```

| 注解 | 说明 |
|------|------|
| `@Mock` | 创建 Mock 对象，模拟依赖行为 |
| `@InjectMocks` | 创建被测对象，并自动注入 Mock 依赖 |

#### 测试数据准备

```java
private Question question;

@BeforeEach
public void setup() {
    question = QuestionFactory.createQuestion();
}
```

每个测试前执行，使用工厂类创建测试数据。

### 2.3 测试用例 1：查询存在的问题

```java
@Test
void get_existed_question_by_show_method() {
    // given
    given(questionMapper.selectByPrimaryKey(1)).willReturn(this.question);

    // when
    QuestionVo existedQuestion = questionService.show(1);

    // then
    assertThat(existedQuestion).isNotNull();
    assertThat(existedQuestion.getId()).isEqualTo(this.question.getId());
    assertThat(existedQuestion.getUserId()).isEqualTo(this.question.getUserId());
    assertThat(existedQuestion.getTitle()).isEqualTo(this.question.getTitle());
    assertThat(existedQuestion.getContent()).isEqualTo(this.question.getContent());
}
```

| 步骤 | 说明 |
|------|------|
| `given(...).willReturn(...)` | 定义 Mock 行为：当查询 ID=1 时，返回测试数据 |
| `questionService.show(1)` | 调用被测方法 |
| `assertThat(...)` | 断言返回的 VO 对象字段正确 |

### 2.4 测试用例 2：查询不存在的问题

```java
@Test
void get_not_existed_question_by_show_method() {
    // given
    given(questionMapper.selectByPrimaryKey(1)).willReturn(null);

    // then
    assertThatThrownBy(() -> {
        // when
        questionService.show(1);
    }).isInstanceOf(QuestionNotExistedException.class)
            .hasMessageStartingWith("question not exist");
}
```

| 步骤 | 说明 |
|------|------|
| `given(...).willReturn(null)` | 定义 Mock 行为：当查询 ID=1 时，返回 null |
| `assertThatThrownBy(...)` | 断言抛出异常 |
| `.isInstanceOf(...)` | 验证异常类型 |
| `.hasMessageStartingWith(...)` | 验证异常消息 |

> 💡 **提示**：通常情况下，是一定需要考虑查询的数据不存在的情况的。所以，我们写了两个测试用例，测试 `QuestionServiceImpl#show()` 方法的完整逻辑。

## 三、运行单元测试

### 3.1 执行测试

```bash
mvn test -Dtest=QuestionServiceImplTest
```

### 3.2 测试结果

![单元测试结果](../../images/episode3_2026-02-08_15-47-03.png)

你会发现：

- ✅ 一个测试通过（查询存在的问题）
- ❌ 一个测试不通过（查询不存在的问题）

并且，**测试运行的速度会非常快**。

### 3.3 测试失败原因

测试不通过的原因很简单：我们并没有在数据不存在的情况下抛出相应的异常。

当前代码：

```java
public QuestionVo show(Integer id) {
    Question question = questionMapper.selectByPrimaryKey(id);
    // ❌ 没有处理 question 为 null 的情况

    QuestionVo questionVo = new QuestionVo();
    questionVo.setId(question.getId());  // 这里会抛出 NullPointerException
    // ...
}
```

## 四、修复代码

### 4.1 添加异常处理

我们完善逻辑：

```java
public QuestionVo show(Integer id) {
    Question question = questionMapper.selectByPrimaryKey(id);
    if (Objects.isNull(question)) {
        throw new QuestionNotExistedException();
    }

    QuestionVo questionVo = new QuestionVo();
    questionVo.setId(question.getId());
    questionVo.setUserId(question.getUserId());
    questionVo.setTitle(question.getTitle());
    questionVo.setContent(question.getContent());

    return questionVo;
}
```

### 4.2 创建异常类

创建文件 *src/main/java/com/nofirst/spring/tdd/zhihu/startup/exception/QuestionNotExistedException.java*：

```java
package com.nofirst.spring.tdd.zhihu.startup.exception;

public class QuestionNotExistedException extends RuntimeException {

    public QuestionNotExistedException() {
        super("question not exist");
    }
}
```

### 4.3 再次运行测试

```bash
mvn test -Dtest=QuestionServiceImplTest
```

测试全部通过！

## 五、集成测试 vs 单元测试

### 5.1 对比总结

| 维度 | 集成测试 | 单元测试 |
|------|---------|---------|
| **测试对象** | Controller 层完整流程 | Service 层业务逻辑 |
| **启动环境** | 完整 Spring 容器 | 无 Spring 容器 |
| **数据库** | 真实数据库（Testcontainers） | Mock 对象 |
| **运行速度** | 慢（10-30 秒） | 快（<1 秒） |
| **测试粒度** | 粗粒度（端到端） | 细粒度（单一方法） |
| **发现问题** | 集成问题、配置问题 | 逻辑错误、边界条件 |
| **维护成本** | 较高 | 较低 |

### 5.2 使用场景

| 场景 | 推荐测试类型 |
|------|------------|
| 验证 API 接口 | 集成测试 |
| 验证业务逻辑 | 单元测试 |
| 验证数据库交互 | 集成测试 |
| 验证边界条件 | 单元测试 |
| 验证异常处理 | 单元测试 |
| 验证权限控制 | 集成测试 |

## 六、测试最佳实践

### 6.1 测试命名

| 测试类型 | 命名风格 | 示例 |
|---------|---------|------|
| 集成测试 | 用户行为描述 | `user_can_view_a_single_question` |
| 单元测试 | 方法行为描述 | `get_existed_question_by_show_method` |

### 6.2 测试组织

```
src/test/java
└── com.nofirst.spring.tdd.zhihu.startup
    ├── integration           # 集成测试
    │   ├── questions
    │   │   └── ViewQuestionsTests.java
    │   └── answers
    │       └── PostAnswerTest.java
    └── unit                  # 单元测试
        ├── service
        │   └── QuestionServiceImplTest.java
        └── policy
            └── QuestionPolicyTest.java
```

### 6.3 测试比例建议

| 测试类型 | 比例 | 说明 |
|---------|------|------|
| 单元测试 | 70% | 快速反馈，覆盖核心逻辑 |
| 集成测试 | 20% | 验证组件协作 |
| 端到端测试 | 10% | 验证关键流程 |

## 七、总结

### 7.1 本节学习要点

| 要点 | 说明 |
|------|------|
| 集成测试 | 启动完整 Spring 环境，测试端到端流程 |
| 单元测试 | 使用 Mock 隔离依赖，测试单一组件 |
| 测试金字塔 | 大量单元测试 + 适量集成测试 |
| 异常测试 | 使用 `assertThatThrownBy` 验证异常 |
| Mock 对象 | 使用 `@Mock` 和 `given().willReturn()` |

### 7.2 两种测试的关系

```
┌─────────────────────────────────────────────────────────┐
│                    测试组合策略                         │
│                                                         │
│   单元测试 ──────→ 快速发现逻辑错误                    │
│       ↓                                                 │
│   集成测试 ──────→ 验证组件协作正常                    │
│       ↓                                                 │
│   端到端测试 ────→ 验证完整业务流程                    │
│                                                         │
│   多层防护，确保代码质量                               │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 附录：常用 Mockito 方法

| 方法 | 说明 | 示例 |
|------|------|------|
| `given().willReturn()` | 定义 Mock 返回值 | `given(mock.get(1)).willReturn(obj)` |
| `given().willThrow()` | 定义 Mock 抛异常 | `given(mock.get(1)).willThrow(new Exception())` |
| `verify()` | 验证方法调用 | `verify(mock).get(1)` |
| `verify(times)` | 验证调用次数 | `verify(mock, times(2)).get(1)` |
| `verifyNever()` | 验证从未调用 | `verify(mock, never()).get(1)` |
| `argumentCaptor()` | 捕获参数 | `ArgumentCaptor<User> captor = argumentCaptor()` |
