### 小结

这一章走了两个完整的 TDD 循环，但规模比上一章大了不少：

1. **集成测试循环**：写测试 → 建表/生成 Mapper/造工厂 → 404 → 加路由 → 断言失败 → 实现 Service → 通过
2. **单元测试循环**：写测试 → 跑不过（缺异常类）→ 创建异常类 → 跑不过（NPE 而非自定义异常）→ 加 null 检查 → 通过

整个过程中，测试逼着你做了几件事：

- **先想清楚再动手**：测试写下了"希望代码长什么样"——`QuestionFactory.createQuestion()`、`QuestionVo` 的字段、`CommonResult.success()` 的返回格式——代码还没写，接口形态已经定了。
- **每次只改一点点**：一个错误接一个错误地修，步子小到几乎不可能引入难以定位的 bug。
- **代码天然可测**：因为测试先于实现，不存在"写完了发现测不了"的尴尬。

另外，你现在手里有两种测试武器了：集成测试验证全链路，单元测试验证单组件。下一章开始，这两种测试会反复交替出现。
