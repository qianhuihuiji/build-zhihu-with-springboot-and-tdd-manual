## 三、核心概念总结

### 3.1 TDD 理念

> 可能你会很不习惯这种方式，认为先写测试是在无中生有。确实，我们是在无中生有。

我们在思考如何写测试代码时，实际上就是我们对功能的构思跟对业务代码的设计，只是这个构思与设计现在还仅仅存在于我们的设想当中，于是我们开始从无到有地开始写代码。

### 3.2 测试的价值

> 当我们的测试通过，这就意味着我们的业务代码开发完成；之后我们对业务代码进行修改时，最开始编写的测试又为我们提供的充足的信心与保护：只要测试能通过，那么修改就是无害的。

这是不是很棒呢？

### 3.3 TDD 开发流程

我们再次强调下 TDD 开发的流程：

> 首先编写一个测试，运行这个测试看着它失败。然后编写最少量的代码取得一些进展，再运行测试。如此不断重复，直到测试通过为止。最后，或许还要重构代码，测试能确保不破坏任何功能。

## 四、小步前进原则

### 4.1 为什么要小步前进？

| 原因 | 说明 |
|------|------|
| **快速反馈** | 及时发现问题，定位更容易 |
| **降低风险** | 每次改动小，出错概率低 |
| **保持信心** | 不断看到进步，增强信心 |
| **易于调试** | 问题范围小，容易定位 |

### 4.2 何谓取得进步？

> **测试从一个错误，进入到下一个错误，即为进步。**

当然，我们的最终目标，就是让我们的测试通过。

### 4.3 错误示例

```java
// ❌ 不好的做法：一次性写太多代码
@Test
void should_do_everything() {
    // 100 行测试代码...
}

// ✅ 好的做法：小步前进
@Test
void user_can_view_questions() { }

@Test
void user_can_view_a_single_question() { }

@Test
void user_can_create_question() { }
```

## 五、测试类型对比

### 5.1 集成测试特点

| 特点 | 说明 |
|------|------|
| 启动完整 Spring 环境 | 测试时间较长 |
| 使用真实数据库 | Testcontainers 创建容器 |
| 测试端到端流程 | 验证组件协作 |
| 适合测试 Controller | 验证 HTTP 请求处理 |

### 5.2 单元测试特点

| 特点 | 说明 |
|------|------|
| 不启动 Spring 容器 | 测试速度快 |
| 使用 Mock 对象 | 隔离外部依赖 |
| 测试单一组件 | 验证业务逻辑 |
| 适合测试 Service | 验证方法逻辑 |

### 5.3 测试金字塔

```
                    /\
                   /  \
                  /    \
                 /      \
                /────────\
               /          \
              /   端到端   \
             /──────────────\
            /                \
           /     集成测试     \
          /────────────────────\
         /                      \
        /       单元测试          \
       /──────────────────────────\
      /                            \
     /──────────────────────────────\
    
    数量多 ← → 数量少
    速度快 ← → 速度慢
    成本低 ← → 成本高
```

### 6.2 核心代码

#### QuestionController

```java
@RestController
@AllArgsConstructor
public class QuestionController {

    private QuestionService questionService;

    @GetMapping("/questions/{id}")
    public QuestionVo show(@PathVariable Integer id) {
        return questionService.show(id);
    }
}
```

#### QuestionServiceImpl

```java
@Service
@AllArgsConstructor
public class QuestionServiceImpl implements QuestionService {

    private QuestionMapper questionMapper;

    @Override
    public QuestionVo show(Integer id) {
        Question question = questionMapper.selectByPrimaryKey(id);
        if (Objects.isNull(question)) {
            throw new QuestionNotExistedException();
        }

        QuestionVo questionVo = new QuestionVo();
        questionVo.setId(question.getId());
        questionVo.setUserId(question.getUserId());
        questionVo.setTitle(question.getTitle());
        questionVo.setContent(question.getContent());

        return questionVo;
    }
}
```

## 八、常见问题

### Q: 为什么测试运行很慢？

**A:** 集成测试会启动完整的 Spring 环境，使用 Testcontainers 创建数据库容器。建议：
- 使用 `withReuse(true)` 复用容器
- 多写单元测试（速度快）
- 只运行相关测试（`-Dtest=MyTest`）

### Q: 什么时候用集成测试，什么时候用单元测试？

**A:** 
- 验证 API 接口、数据库交互 → 集成测试
- 验证业务逻辑、边界条件 → 单元测试

### Q: 为什么要小步前进？

**A:** 
- 快速反馈，及时发现问题
- 降低风险，每次改动小
- 保持信心，不断看到进步
