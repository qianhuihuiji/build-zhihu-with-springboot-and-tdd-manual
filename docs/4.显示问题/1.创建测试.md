# 创建测试

在上一节，我们已经成功运行了一个测试，那是我们的入门测试。你也一定注意到了，我们没有放置真正的逻辑在测试代码中。是的，它是为了让你简单了解 `TDD` 开发的流程。

让我们先将它放在一边，下面，正式开始我们的测试之旅。

---

## 一、心理准备

在开始之前，我提前给你打个预防针：

> **有些地方会出错，你看到的结果可能和我说的不一样。**

这是好事，因为这才是磨练意志的学习经历。

### 可能出现的问题

| 原因 | 说明 | 解决方法 |
|------|------|---------|
| **教程表述不清** | 让你产生了误解 | 退一步想想要实现的是什么，在编辑哪个文件，想让用户做些什么 |
| **编辑了错误的文件** | 修改了不该修改的地方 | 停下来想一想，能更好地学习 TDD |
| **运行了其他测试** | 测试环境不一致 | 确认运行的是当前测试类 |
| **代码真有 bug** | 确实存在问题 | 认真阅读错误消息，找到原因 |

> 💡 **提示**：不要害怕出错，这种调试也是学习过程的重要组成部分，所以一定要坚持到底！

### 2.2 完整测试代码

我们在上面的代码写上我们的思路，现在我们补充上代码：

```java
package com.nofirst.spring.tdd.zhihu.startup.integration;

import com.fasterxml.jackson.databind.ObjectMapper;
import com.nofirst.spring.tdd.zhihu.startup.factory.QuestionFactory;
import com.nofirst.spring.tdd.zhihu.startup.mbg.mapper.QuestionMapper;
import com.nofirst.spring.tdd.zhihu.startup.mbg.model.Question;
import com.nofirst.spring.tdd.zhihu.startup.mbg.model.QuestionExample;
import com.nofirst.spring.tdd.zhihu.startup.model.vo.QuestionVo;
import org.junit.jupiter.api.BeforeAll;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.api.TestInstance;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.http.MediaType;
import org.springframework.test.web.servlet.MockMvc;
import org.springframework.test.web.servlet.setup.MockMvcBuilders;
import org.springframework.web.context.WebApplicationContext;

import static org.assertj.core.api.Assertions.assertThat;
import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.get;
import static org.springframework.test.web.servlet.result.MockMvcResultMatchers.status;

// 添加 TestInstance 注解，设置为 PER_CLASS 模式，允许@BeforeAll 使用非 static 方法
@TestInstance(TestInstance.Lifecycle.PER_CLASS)
public class ViewQuestionsTests extends BaseContainerTest {

    private MockMvc mockMvc;

    @Autowired
    private WebApplicationContext context;

    @Autowired
    private QuestionMapper questionMapper;

    @Autowired
    private ObjectMapper objectMapper;


    @BeforeAll
    public void setupMockMvc() {
        mockMvc = MockMvcBuilders
                .webAppContextSetup(context)
                .build();
    }

    @BeforeEach
    public void setupTestData() {
        QuestionExample example = new QuestionExample();
        // 空条件，匹配所有数据，等价于 delete * from question
        example.createCriteria();
        questionMapper.deleteByExample(example);
    }

    @Test
    void user_can_view_questions() throws Exception {
        // given

        // when
        this.mockMvc.perform(get("/questions"))
                // then
                .andExpect(status().isOk()).andReturn();
    }

    @Test
    void user_can_view_a_single_question() throws Exception {
        // given：准备测试数据
        Question question = QuestionFactory.createQuestion();
        questionMapper.insert(question);

        // when：调用接口并获取返回结果
        String jsonResponse = this.mockMvc.perform(
                        get("/questions/{id}", question.getId())
                                .accept(MediaType.APPLICATION_JSON)
                )
                .andExpect(status().isOk())
                .andReturn()
                .getResponse()
                .getContentAsString();

        // then：1. 解析 JSON 为 QuestionVo（结构不匹配时此处直接报错）
        QuestionVo questionVo = objectMapper.readValue(jsonResponse, QuestionVo.class);

        // then：2. 断言 QuestionVo 的核心字段（覆盖所有关键字段）
        assertThat(questionVo.getId()).isEqualTo(question.getId());
        assertThat(questionVo.getUserId()).isEqualTo(question.getUserId());
        assertThat(questionVo.getTitle()).isEqualTo(question.getTitle());
        assertThat(questionVo.getContent()).isEqualTo(question.getContent());
    }

}
```

### 3.3 新测试方法解析

```java
@Test
void user_can_view_a_single_question() throws Exception {
    // given：准备测试数据
    Question question = QuestionFactory.createQuestion();
    questionMapper.insert(question);
```

| 步骤 | 说明 |
|------|------|
| `QuestionFactory.createQuestion()` | 使用工厂类创建测试数据 |
| `questionMapper.insert(question)` | 将问题插入数据库 |

```java
    // when：调用接口并获取返回结果
    String jsonResponse = this.mockMvc.perform(
                    get("/questions/{id}", question.getId())
                            .accept(MediaType.APPLICATION_JSON)
            )
            .andExpect(status().isOk())
            .andReturn()
            .getResponse()
            .getContentAsString();
```

| 步骤 | 说明 |
|------|------|
| `get("/questions/{id}", question.getId())` | 访问问题详情接口 |
| `.accept(MediaType.APPLICATION_JSON)` | 指定接受 JSON 格式 |
| `.andExpect(status().isOk())` | 断言状态码为 200 |
| `.andReturn().getResponse().getContentAsString()` | 获取响应内容字符串 |

```java
    // then：1. 解析 JSON 为 QuestionVo（结构不匹配时此处直接报错）
    QuestionVo questionVo = objectMapper.readValue(jsonResponse, QuestionVo.class);

    // then：2. 断言 QuestionVo 的核心字段（覆盖所有关键字段）

    assertThat(questionVo.getTitle()).isEqualTo(question.getTitle());
    assertThat(questionVo.getContent()).isEqualTo(question.getContent());
}
```

| 步骤 | 说明 |
|------|------|
| `objectMapper.readValue()` | 将 JSON 字符串解析为 QuestionVo 对象 |

## 四、运行测试

### 4.1 执行测试

```bash
mvn test -Dtest=ViewQuestionsTests
```

### 4.2 预期错误

恐怕现在你的编辑器正在告诉你，你的代码有问题！是的，我们的代码有问题，我们知道。

但是，`TDD` 的理念就是：

> **先写出不存在的代码**

我们知道某些类还不存在、某个方法还不存在；然而，这些类与方法是基于我们的设计而存在的，这正是我们前进的方向。

### 4.3 可能出现的错误

| 错误 | 原因 | 下一步 |
|------|------|--------|
| `QuestionFactory` 不存在 | 工厂类未创建 | 下一节创建工厂类 |
| `QuestionMapper` 不存在 | 数据库表未创建 | 下一节创建数据表 |
| `QuestionVo` 不存在 | 视图对象未创建 | 后续创建 |

## 五、TDD 理念

### 5.1 红 - 绿 - 重构循环

```
┌─────────────────────────────────────────────────────────┐
│                   TDD 开发循环                          │
│                                                         │
│    ┌─────────┐     ┌─────────┐     ┌─────────┐        │
│    │  编写   │     │  运行   │     │  重构   │        │
│    │  测试   │ ──→ │  测试   │ ──→ │  代码   │        │
│    │ (失败)  │     │ (通过)  │     │         │        │
│    └─────────┘     └─────────┘     └─────────┘        │
│         ↑              │                              │
│         │              │                              │
│         └──────────────┘                              │
│              编写最少代码                              │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 5.2 为什么先写测试？

| 原因 | 说明 |
|------|------|
| **明确需求** | 测试即需求，写测试前先想清楚要什么 |
| **设计驱动** | 测试代码影响业务代码设计 |
| **信心保障** | 测试通过后，重构有保护网 |
| **文档价值** | 测试即文档，说明代码如何使用 |
