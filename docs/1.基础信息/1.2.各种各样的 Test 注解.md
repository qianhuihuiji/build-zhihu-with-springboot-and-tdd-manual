# 各种各样的 Test 注解

在本教程中，我们使用了大量的测试注解。本文档将总结这些注解的用法，并使用本教程中的实际代码作为示例进行讲解。

---

## 一、JUnit 5 基础注解

### 1.1 @Test

**用途**：标记一个方法为测试方法。

**示例**：

```java
@Test
void user_can_view_questions() throws Exception {
    // given

    // when
    this.mockMvc.perform(get("/questions"))
            // then
            .andExpect(status().isOk());
}
```

**说明**：
- 被 `@Test` 注解标记的方法会被 JUnit 识别为测试方法
- 测试方法应该是 `public` 的，返回类型可以是 `void`
- 测试方法可以抛出异常

---

### 1.2 @TestInstance

**用途**：配置测试实例的生命周期。

**示例**：

```java
@TestInstance(TestInstance.Lifecycle.PER_CLASS)
public class ViewQuestionsTest extends BaseContainerTest {

    private MockMvc mockMvc;

    @Autowired
    private WebApplicationContext context;

    @BeforeAll
    public void setupMockMvc() {
        mockMvc = MockMvcBuilders
                .webAppContextSetup(context)
                .build();
    }
}
```

**说明**：

| 生命周期 | 说明 | 使用场景 |
|---------|------|---------|
| `PER_METHOD` (默认) | 每个测试方法创建新实例 | 默认情况 |
| `PER_CLASS` | 整个测试类只创建一个实例 | `@BeforeAll` 需要使用非静态方法时 |

**为什么需要 PER_CLASS？**

默认情况下，JUnit 5 为每个测试方法创建新实例，因此 `@BeforeAll` 方法必须是 `static` 的。使用 `PER_CLASS` 后，整个测试类只创建一个实例，`@BeforeAll` 可以是非静态的，方便访问实例变量。

---

### 1.3 @BeforeEach

**用途**：在每个测试方法执行之前运行。

**示例**：

```java
@BeforeEach
public void setupTestData() {
    QuestionExample questionExample = new QuestionExample();
    // 空条件，匹配所有数据，等价于 delete * from question
    questionExample.createCriteria();
    questionMapper.deleteByExample(questionExample);
    
    CommentExample commentExample = new CommentExample();
    commentExample.createCriteria();
    commentMapper.deleteByExample(commentExample);
}
```

**说明**：
- 每个测试方法执行前都会运行
- 用于准备测试数据、初始化环境
- 保证测试之间的独立性

---

### 1.4 @AfterEach

**用途**：在每个测试方法执行之后运行。

**示例**：

```java
@AfterEach
public void tearDown() {
    // 清理测试数据
    questionMapper.deleteByExample(null);
}
```

**说明**：
- 每个测试方法执行后都会运行
- 用于清理测试数据、释放资源

---

### 1.5 @BeforeAll

**用途**：在所有测试方法执行之前运行一次。

**示例**：

```java
@BeforeAll
public void setupMockMvc() {
    mockMvc = MockMvcBuilders
            .webAppContextSetup(context)
            .apply(springSecurity())
            .build();
}
```

**说明**：
- 只运行一次，在所有测试之前
- 默认需要 `static` 方法（配合 `@TestInstance(PER_METHOD)`）
- 使用 `@TestInstance(PER_CLASS)` 可以是非静态方法
- 用于初始化共享资源，如 MockMvc

---

### 1.6 @AfterAll

**用途**：在所有测试方法执行之后运行一次。

**示例**：

```java
@AfterAll
public void cleanAll() {
    // 清理共享资源
    mockMvc = null;
}
```

**说明**：
- 只运行一次，在所有测试之后
- 默认需要 `static` 方法
- 用于清理共享资源

---

### 1.7 @DisplayName

**用途**：为测试类或测试方法设置显示名称。

**示例**：

```java
@DisplayName("问题列表测试")
class ViewQuestionsTest {

    @Test
    @DisplayName("用户可以查看问题列表")
    void user_can_view_questions() {
        // ...
    }
}
```

**说明**：
- 提高测试报告的可读性
- 支持中文和特殊字符

---

### 1.8 @Nested

**用途**：嵌套测试类，用于组织测试结构。

**示例**：

```java
@Nested
@DisplayName("未登录用户")
class GuestTests {
    
    @Test
    @DisplayName("不能评论问题")
    void guests_may_not_comment_a_question() {
        // ...
    }
}

@Nested
@DisplayName("已登录用户")
class SignedInUserTests {
    
    @Test
    @DisplayName("可以评论已发布的问题")
    void signed_in_user_can_comment_a_published_question() {
        // ...
    }
}
```

**说明**：
- 将相关测试组织在一起
- 提高测试代码的可读性和可维护性

---

### 1.9 @Disabled

**用途**：禁用测试类或测试方法。

**示例**：

```java
@Test
@Disabled("暂时跳过，待修复")
void some_broken_test() {
    // ...
}
```

**说明**：
- 临时禁用测试
- 可以添加原因说明

---

### 1.10 @Tag

**用途**：为测试添加标签，用于分类和过滤。

**示例**：

```java
@Test
@Tag("online")
void can_translate_chinese_to_english() {
    // given
    BaiduTranslatorServiceImpl translatorService = new BaiduTranslatorServiceImpl(translatorConfig);
    String text = "英语 英语";
    // when
    String translate = translatorService.translate(text);
    // then
    assertThat(translate).isEqualTo("english-english");
}
```

**说明**：
- 用于标记特殊类型的测试（如在线测试、慢速测试）
- 可以在 IDE 中配置排除特定标签的测试
- 本教程中用于标记需要网络请求的测试

## 二、Spring Boot Test 注解

### 2.1 @SpringBootTest

**用途**：加载完整的 Spring 应用上下文，用于集成测试。

**示例**：

```java
@SpringBootTest(classes = SpringTddZhihuStartupApplication.class)
public abstract class BaseContainerTest {
    // ...
}
```

**说明**：
- 加载完整的 Spring 容器
- 用于集成测试
- 可以指定配置类

---

### 2.2 @AutoConfigureMockMvc

**用途**：自动配置 MockMvc Bean。

**示例**：

```java
@SpringBootTest
@AutoConfigureMockMvc
class QuestionControllerTest {

    @Autowired
    private MockMvc mockMvc;
    
    @Test
    void should_return_questions() throws Exception {
        mockMvc.perform(get("/questions"))
            .andExpect(status().isOk());
    }
}
```

**说明**：
- 自动配置 MockMvc
- 可以直接注入使用
- 通常与 `@SpringBootTest` 一起使用

---

### 2.3 @WebMvcTest

**用途**：仅加载 Web 层（Controller 相关），用于切片测试。

**示例**：

```java
@WebMvcTest(QuestionController.class)
class QuestionControllerTest {

    @Autowired
    private MockMvc mockMvc;
    
    @MockBean
    private QuestionService questionService;
    
    @Test
    void should_return_questions() throws Exception {
        given(questionService.getAllQuestions()).willReturn(Collections.emptyList());
        
        mockMvc.perform(get("/questions"))
            .andExpect(status().isOk());
    }
}
```

**说明**：
- 只加载 Controller 层
- 不加载 Service、Repository 层
- 测试速度更快
- 需要使用 `@MockBean` Mock 依赖

---

### 2.4 @DataJpaTest

**用途**：仅加载数据层（JPA/MyBatis 相关），用于数据层测试。

**示例**：

```java
@DataJpaTest
class QuestionMapperTest {

    @Autowired
    private QuestionMapper questionMapper;
    
    @Test
    void should_insert_question() {
        Question question = new Question();
        question.setTitle("测试问题");
        questionMapper.insert(question);
        
        assertThat(question.getId()).isNotNull();
    }
}
```

**说明**：
- 只加载数据层
- 自动配置内存数据库（测试用）
- 自动回滚事务

---

### 2.5 @MockBean

**用途**：将 Mock 对象添加到 Spring 应用上下文。

**示例**：

```java
@WebMvcTest(QuestionController.class)
class QuestionControllerTest {

    @MockBean
    private QuestionService questionService;
    
    @Autowired
    private QuestionController questionController;
    
    @Test
    void should_return_questions() throws Exception {
        given(questionService.getAllQuestions()).willReturn(Collections.emptyList());
        // ...
    }
}
```

**说明**：
- 创建 Mock 对象并注册到 Spring 容器
- 替换容器中同名的 Bean
- 用于隔离测试

---

### 2.6 @ActiveProfiles

**用途**：指定激活的 Spring Profile。

**示例**：

```java
@SpringBootTest
@ActiveProfiles("test")
class IntegrationTest {
    // ...
}
```

**说明**：
- 激活特定的配置环境
- 常用于测试环境配置

---

## 三、Mockito 注解

### 3.1 @ExtendWith(MockitoExtension.class)

**用途**：启用 Mockito 扩展，自动初始化 Mock 对象。

**示例**：

```java
@ExtendWith(MockitoExtension.class)
class QuestionServiceImplTest {

    @InjectMocks
    private QuestionServiceImpl questionService;

    @Mock
    private QuestionMapper questionMapper;

    @Test
    void get_existed_question_by_show_method() {
        // given
        given(questionMapper.selectByPrimaryKey(1)).willReturn(this.question);

        // when
        QuestionVo existedQuestion = questionService.show(1);

        // then
        assertThat(existedQuestion).isNotNull();
    }
}
```

**说明**：
- 启用 Mockito 注解支持
- 自动初始化 `@Mock`、`@InjectMocks` 等注解

---

### 3.2 @Mock

**用途**：创建 Mock 对象。

**示例**：

```java
@Mock
private QuestionMapper questionMapper;

@Mock
private AnswerMapper answerMapper;
```

**说明**：
- 创建 Mock 对象
- 默认行为返回 null、空集合或 false

---

### 3.3 @InjectMocks

**用途**：创建被测对象，并自动注入 Mock 依赖。

**示例**：

```java
@InjectMocks
private QuestionServiceImpl questionService;

@Mock
private QuestionMapper questionMapper;
```

**说明**：
- 创建被测对象实例
- 自动将 `@Mock` 创建的对象注入到被测对象
- 支持构造函数注入、Setter 注入、字段注入

---

### 3.4 @Spy

**用途**：创建部分模拟对象（保留原对象行为）。

**示例**：

```java
@Spy
private QuestionServiceImpl questionService;

@Test
void should_call_real_method() {
    // 调用真实方法
    questionService.realMethod();
    
    // 验证调用
    verify(questionService).realMethod();
}
```

**说明**：
- 创建 Spy 对象
- 默认调用真实方法
- 可以 Stub 特定方法

---

### 3.5 @Captor

**用途**：捕获参数用于验证。

**示例**：

```java
@Captor
private ArgumentCaptor<Question> questionCaptor;

@Test
void should_save_question() {
    // when
    questionService.save(question);
    
    // then
    verify(questionMapper).insert(questionCaptor.capture());
    Question captured = questionCaptor.getValue();
    assertThat(captured.getTitle()).isEqualTo("测试");
}
```

**说明**：
- 捕获传递给 Mock 方法的参数
- 用于复杂参数的验证

---

## 四、Testcontainers 注解

### 4.1 @Testcontainers

**用途**：启用 Testcontainers 支持。

**示例**：

```java
@Testcontainers
@SpringBootTest
public abstract class BaseContainerTest {

    @Container
    static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0")
        .withDatabaseName("test_db")
        .withUsername("test")
        .withPassword("test")
        .withReuse(true);

    @DynamicPropertySource
    static void configureTestProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", mysql::getJdbcUrl);
        registry.add("spring.datasource.username", mysql::getUsername);
        registry.add("spring.datasource.password", mysql::getPassword);
    }
}
```

**说明**：
- 启用 Testcontainers 支持
- 自动管理容器生命周期
- 通常与 `@SpringBootTest` 一起使用

---

### 4.2 @Container

**用途**：标记容器实例。

**示例**：

```java
@Container
static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0")
    .withDatabaseName("test_db")
    .withReuse(true);
```

**说明**：
- 标记容器字段
- Testcontainers 自动管理容器生命周期
- 通常与 `@Testcontainers` 一起使用

---

### 4.3 @DynamicPropertySource

**用途**：动态配置测试属性。

**示例**：

```java
@DynamicPropertySource
static void properties(DynamicPropertyRegistry registry) {
    registry.add("spring.datasource.url", mysqlContainer::getJdbcUrl);
    registry.add("spring.datasource.password", mysqlContainer::getPassword);
    registry.add("spring.datasource.username", mysqlContainer::getUsername);
    registry.add("spring.kafka.bootstrap-servers", kafkaContainer::getBootstrapServers);
    registry.add("spring.data.redis.host", redisContainer::getHost);
    registry.add("spring.data.redis.port", redisContainer::getFirstMappedPort);
}
```

**说明**：
- 动态设置 Spring 配置属性
- 用于将容器连接信息传递给 Spring
- 方法必须是 `static` 的

## 五、Spring Security Test 注解

### 5.1 @WithMockUser

**用途**：模拟登录用户。

**示例**：

```java
@Test
@WithMockUser
void can_mark_one_answer_as_the_best() throws Exception {
    // given：准备测试数据
    Question question = QuestionFactory.createPublishedQuestion();
    questionMapper.insert(question);
    Answer answer = AnswerFactory.createAnswer(question.getId());
    answerMapper.insert(answer);

    // when
    this.mockMvc.perform(post("/answers/{answerId}/best", answer.getId())
                    .contentType(MediaType.APPLICATION_JSON)
            ).andDo(print())
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.code").value(ResultCode.SUCCESS.getCode()));
}
```

**说明**：
- 模拟一个登录用户
- 默认用户名 "user"，角色 "USER"
- 可以自定义用户名、角色

---

### 5.2 @WithUserDetails

**用途**：使用用户详情模拟登录。

**示例**：

```java
@Test
@WithUserDetails(value = "John", userDetailsServiceBeanName = "customUserDetailsService")
void signed_in_user_can_post_an_answer_to_a_published_question() throws Exception {
    // given：准备测试数据
    Question question = QuestionFactory.createPublishedQuestion();
    questionMapper.insert(question);
    
    // when
    AnswerDto answer = AnswerFactory.createAnswerDto();
    this.mockMvc.perform(post("/questions/{id}/answers", question.getId())
                    .contentType(MediaType.APPLICATION_JSON)
                    .content(objectMapper.writeValueAsString(answer))
            )
            .andExpect(status().isOk());
}
```

**说明**：
- 使用真实的 UserDetailsService 加载用户
- 可以指定用户名和 UserDetailsService Bean 名称
- 适用于需要真实用户数据的场景

### 6.1 集成测试基类

### 6.2 集成测试示例

```java
@TestInstance(TestInstance.Lifecycle.PER_CLASS)
public class QuestionCommentsTest extends BaseContainerTest {

    private MockMvc mockMvc;

    @Autowired
    private WebApplicationContext context;

    @Autowired
    private QuestionMapper questionMapper;

    @Autowired
    private CommentMapper commentMapper;

    @Autowired
    private ObjectMapper objectMapper;

    @BeforeAll
    public void setupMockMvc() {
        mockMvc = MockMvcBuilders
                .webAppContextSetup(context)
                .apply(springSecurity())
                .build();
    }

    @BeforeEach
    public void setupTestData() {
        QuestionExample questionExample = new QuestionExample();
        questionExample.createCriteria();
        questionMapper.deleteByExample(questionExample);
        
        CommentExample commentExample = new CommentExample();
        commentExample.createCriteria();
        commentMapper.deleteByExample(commentExample);
    }

    @Test
    void guests_may_not_comment_a_question() throws Exception {
        this.mockMvc.perform(post("/comments/questions/1"))
                .andDo(print())
                .andExpect(status().is(401));
    }

    @Test
    @WithUserDetails(value = "John", userDetailsServiceBeanName = "customUserDetailsService")
    void signed_in_user_can_comment_a_published_question() throws Exception {
        // given
        Question question = QuestionFactory.createPublishedQuestion();
        questionMapper.insert(question);

        long beforeCount = commentMapper.countByExample(null);
        assertThat(beforeCount).isEqualTo(0);

        // when
        CommentDto commentDto = new CommentDto();
        commentDto.setContent("this is a comment");
        this.mockMvc.perform(post("/comments/questions/{questionId}", question.getId())
                        .contentType(MediaType.APPLICATION_JSON)
                        .content(objectMapper.writeValueAsString(commentDto))
                ).andDo(print())
                .andExpect(status().isOk());

        // then
        CommentExample example = new CommentExample();
        CommentExample.Criteria criteria = example.createCriteria();
        criteria.andCommentedIdEqualTo(question.getId());
        criteria.andCommentedTypeEqualTo(Question.class.getSimpleName());
        long afterCount = commentMapper.countByExample(example);
        assertThat(afterCount).isEqualTo(1);
    }

    @Test
    @WithUserDetails(value = "John", userDetailsServiceBeanName = "customUserDetailsService")
    void content_is_required_to_comment_a_question() throws Exception {
        // given
        Question question = QuestionFactory.createPublishedQuestion();
        questionMapper.insert(question);

        // when
        CommentDto commentDto = new CommentDto();
        commentDto.setContent(null);
        this.mockMvc.perform(post("/comments/questions/{questionId}", question.getId())
                        .contentType(MediaType.APPLICATION_JSON)
                        .content(objectMapper.writeValueAsString(commentDto))
                ).andDo(print())
                .andExpect(jsonPath("$.code").value(ResultCode.VALIDATE_FAILED.getCode()))
                .andExpect(jsonPath("$.message").value("评论内容不能为空"));
    }
}
```

### 6.3 单元测试示例

```java
@ExtendWith(MockitoExtension.class)
class QuestionServiceImplTest {

    @InjectMocks
    private QuestionServiceImpl questionService;

    @Mock
    private QuestionMapper questionMapper;

    private Question question;

    @BeforeEach
    public void setup() {
        question = QuestionFactory.createQuestion();
        Date lastWeek = DateUtils.addWeeks(new Date(), -1);
        question.setPublishedAt(lastWeek);
    }

    @Test
    void get_existed_question_by_show_method() {
        // given
        given(questionMapper.selectByPrimaryKey(1)).willReturn(this.question);

        // when
        QuestionVo existedQuestion = questionService.show(1);

        // then
        assertThat(existedQuestion).isNotNull();
        assertThat(existedQuestion.getId()).isEqualTo(this.question.getId());
        assertThat(existedQuestion.getUserId()).isEqualTo(this.question.getUserId());
        assertThat(existedQuestion.getTitle()).isEqualTo(this.question.getTitle());
        assertThat(existedQuestion.getContent()).isEqualTo(this.question.getContent());
    }

    @Test
    void get_not_existed_question_by_show_method() {
        // given
        given(questionMapper.selectByPrimaryKey(1)).willReturn(null);

        // then
        assertThatThrownBy(() -> {
            // when
            questionService.show(1);
        }).isInstanceOf(QuestionNotExistedException.class)
                .hasMessageStartingWith("question not exist");
    }

    @Test
    void get_not_published_question_by_show_method() {
        // given
        this.question.setPublishedAt(null);
        given(questionMapper.selectByPrimaryKey(1)).willReturn(this.question);

        // then
        assertThatThrownBy(() -> {
            // when
            questionService.show(1);
        }).isInstanceOf(QuestionNotPublishedException.class)
                .hasMessageStartingWith("question not publish");
    }
}
```

### Spring Security Test

| 注解 | 用途 |
|------|------|
| `@WithMockUser` | 模拟登录用户 |
| `@WithUserDetails` | 使用用户详情模拟登录 |

## 八、测试方法命名规范

### 蛇形命名（推荐）

本教程采用**蛇形命名（下划线风格）**作为测试方法的命名规范：

```java
// ✅ 推荐：蛇形命名
@Test
void user_can_view_questions() { }

@Test
void guest_can_not_comment_a_question() { }

@Test
void signed_in_user_can_post_an_answer_to_a_published_question() { }
```

### 命名模板

```java
@Test
void [角色]_[动作]_[预期结果]() {
    // 示例
}

@Test
void user_can_view_questions() { }

@Test
void guest_cannot_create_question() { }

@Test
void signed_in_user_can_answer_question() { }
```

### 蛇形命名的优势

| 优势 | 说明 |
|------|------|
| 可读性更好 | 像一句完整的描述 |
| 清晰表达意图 | 一眼看出测试目的 |
| 符合 BDD 理念 | 行为驱动开发风格 |

## 九、总结

通过本教程的学习，我们掌握了以下测试注解的使用：

1. **JUnit 5 基础注解**：`@Test`、`@BeforeEach`、`@BeforeAll` 等
2. **Spring Boot Test 注解**：`@SpringBootTest`、`@WebMvcTest`、`@MockBean` 等
3. **Mockito 注解**：`@Mock`、`@InjectMocks`、`@Spy` 等
4. **Testcontainers 注解**：`@Testcontainers`、`@Container`、`@DynamicPropertySource`
5. **Spring Security Test 注解**：`@WithMockUser`、`@WithUserDetails`

这些注解帮助我们编写了清晰、可维护的测试代码，是 Spring Boot 应用测试的重要工具。

> 💡 **提示**：本教程所有测试方法均采用**蛇形命名**风格，以提高测试代码的可读性。
