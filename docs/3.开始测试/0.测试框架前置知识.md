# 测试框架前置知识

在开始编写测试之前，我们需要了解本项目使用的测试框架和工具。本章将详细介绍这些工具的核心概念和基本用法。

---

## 一、测试框架概览

本项目的测试技术栈如下：

```
测试技术栈
├── JUnit 5          # 测试框架
├── Spring Boot Test # Spring 测试支持
├── AssertJ          # Fluent 断言库
├── Mockito          # Mock 框架
├── Testcontainers   # 容器化测试工具
└── MockMvc          # Web 层测试工具
```

这些工具都包含在 `spring-boot-starter-test` 依赖中，或作为独立依赖引入。

## 二、spring-boot-starter-test

Spring Boot 提供的测试启动器，包含了测试所需的核心依赖。

### 依赖引入

在 `pom.xml` 中添加：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>
```

### 包含的库

| 库 | 说明 | 用途 |
|----|------|------|
| **JUnit 5** | 单元测试框架 | 编写和运行测试 |
| **Spring Test & Spring Boot Test** | Spring 测试支持 | 集成测试支持 |
| **AssertJ** | Fluent 断言库 | 编写可读的断言 |
| **Hamcrest** | 匹配器库 | 配合断言使用 |
| **Mockito** | Mock 框架 | 创建模拟对象 |
| **JSONassert** | JSON 断言库 | 测试 JSON 响应 |
| **JsonPath** | JSON 路径解析 | 提取 JSON 数据 |

> 📖 官方文档：https://springdoc.cn/spring-boot/features.html#features.testing

## 三、JUnit 5

JUnit 5 是 Java 单元测试的事实标准，由三个子模块组成：

```
JUnit 5 = JUnit Platform + JUnit Jupiter + JUnit Vintage
```

| 模块 | 说明 |
|------|------|
| **JUnit Platform** | 测试平台，负责启动测试 |
| **JUnit Jupiter** | JUnit 5 的新编程模型（我们主要使用这个） |
| **JUnit Vintage** | 兼容 JUnit 3/4 的引擎 |

### 常用注解

| 注解 | 说明 | 使用场景 |
|------|------|---------|
| `@Test` | 标记测试方法 | 每个测试方法 |
| `@BeforeEach` | 每个测试前执行 | 初始化测试数据 |
| `@AfterEach` | 每个测试后执行 | 清理测试数据 |
| `@BeforeAll` | 所有测试前执行一次 | 初始化共享资源 |
| `@AfterAll` | 所有测试后执行一次 | 清理共享资源 |
| `@DisplayName` | 设置测试名称 | 提高测试可读性 |
| `@Disabled` | 禁用测试 | 临时跳过测试 |
| `@Nested` | 嵌套测试类 | 组织测试结构 |
| `@TestInstance` | 配置测试实例生命周期 | 配合 `@BeforeAll` 使用 |

### 示例代码

```java
@TestInstance(TestInstance.Lifecycle.PER_CLASS)
class UserServiceTest {

    @Autowired
    private UserService userService;

    @BeforeAll
    void initAll() {
        // 所有测试前执行一次
    }

    @BeforeEach
    void setUp() {
        // 每个测试前执行
    }

    @Test
    @DisplayName("应该成功创建用户")
    void shouldCreateUser() {
        // 测试逻辑
    }

    @AfterEach
    void tearDown() {
        // 每个测试后执行
    }

    @AfterAll
    void cleanAll() {
        // 所有测试后执行一次
    }
}
```

### 重要提示

使用 `@BeforeAll` 和 `@AfterAll` 时，需要配置测试实例生命周期：

```java
@TestInstance(TestInstance.Lifecycle.PER_CLASS)
class MyTest {
    @BeforeAll
    void init() {
        // 非静态方法也可以
    }
}
```

默认情况下，JUnit 5 为每个测试方法创建新的测试实例，因此 `@BeforeAll` 方法必须是 `static` 的。使用 `PER_CLASS` 后，整个测试类只创建一个实例，`@BeforeAll` 方法可以是非静态的。

## 四、AssertJ 断言库

AssertJ 是一个 Fluent 风格的断言库，提供更自然、可读的断言语法。

### 基本用法

```java
import static org.assertj.core.api.Assertions.assertThat;

// 基本断言
assertThat(user.getName()).isEqualTo("John");
assertThat(user.getAge()).isGreaterThan(18);
assertThat(user.getEmail()).isNotNull();

// 集合断言
assertThat(users).hasSize(5);
assertThat(users).extracting("name").contains("John", "Jane");
assertThat(users).filteredOn("age", 25).hasSize(2);

// 异常断言
assertThatThrownBy(() -> userService.delete(null))
    .isInstanceOf(IllegalArgumentException.class)
    .hasMessage("用户 ID 不能为空");
```

### 常用断言方法

| 断言 | 说明 |
|------|------|
| `isEqualTo()` | 等于 |
| `isNotEqualTo()` | 不等于 |
| `isNull()` / `isNotNull()` | 为空/不为空 |
| `isTrue()` / `isFalse()` | 布尔值判断 |
| `contains()` | 包含 |
| `doesNotContain()` | 不包含 |
| `startsWith()` / `endsWith()` | 字符串开头/结尾 |
| `isGreaterThan()` / `isLessThan()` | 数值比较 |
| `hasSize()` | 集合大小 |
| `isEmpty()` / `isNotEmpty()` | 集合为空/不为空 |
| `extracting()` | 提取对象属性 |
| `filteredOn()` | 过滤集合 |

### 对比 JUnit 断言

```java
// JUnit 5 断言
assertEquals(expected, actual);
assertTrue(condition);
assertNotNull(object);

// AssertJ 断言（更可读）
assertThat(actual).isEqualTo(expected);
assertThat(condition).isTrue();
assertThat(object).isNotNull();
```

> 📖 官方文档：https://assertj.github.io/

## 五、Mockito Mock 框架

Mockito 用于创建和管理模拟对象，隔离被测代码的外部依赖。

### 常用注解

| 注解 | 说明 |
|------|------|
| `@Mock` | 创建模拟对象 |
| `@InjectMocks` | 自动注入 Mock 到被测对象 |
| `@Spy` | 创建部分模拟对象（保留原对象行为） |
| `@Captor` | 捕获参数用于验证 |

### 基本用法

```java
@ExtendWith(MockitoExtension.class)
class UserServiceTest {

    @Mock
    private UserMapper userMapper;

    @InjectMocks
    private UserService userService;

    @Test
    void shouldReturnUser() {
        // 1. 定义 Mock 行为
        User mockUser = new User();
        mockUser.setId(1);
        mockUser.setName("John");
        when(userMapper.selectByPrimaryKey(1)).thenReturn(mockUser);

        // 2. 执行测试
        User result = userService.getUserById(1);

        // 3. 验证结果
        assertThat(result.getName()).isEqualTo("John");
        
        // 4. 验证交互
        verify(userMapper).selectByPrimaryKey(1);
    }
}
```

### 常用方法

| 方法 | 说明 |
|------|------|
| `when().thenReturn()` | 定义 Mock 返回值 |
| `when().thenThrow()` | 定义 Mock 抛出异常 |
| `verify()` | 验证方法是否被调用 |
| `verifyNever()` | 验证方法从未被调用 |
| `verify(times)` | 验证方法被调用次数 |
| `argumentCaptor()` | 捕获传入的参数 |

### 示例：验证异常

```java
@Test
void shouldThrowException() {
    // 定义 Mock 抛出异常
    when(userMapper.selectByPrimaryKey(null))
        .thenThrow(new IllegalArgumentException("ID 不能为空"));

    // 验证异常抛出
    assertThatThrownBy(() -> userService.getUserById(null))
        .isInstanceOf(IllegalArgumentException.class)
        .hasMessage("ID 不能为空");
}
```

> 📖 官方文档：https://site.mockito.org/

## 六、Spring Boot Test

Spring Boot 提供的测试支持，简化 Spring 应用的集成测试。

### 常用注解

| 注解 | 说明 |
|------|------|
| `@SpringBootTest` | 加载完整的 Spring 应用上下文 |
| `@WebMvcTest` | 仅加载 Web 层（Controller 相关） |
| `@DataJpaTest` | 仅加载数据层（JPA/MyBatis 相关） |
| `@MockBean` | 将 Mock 对象添加到 Spring 上下文 |
| `@AutoConfigureMockMvc` | 自动配置 MockMvc |
| `@ActiveProfiles` | 指定激活的 Profile |

### 示例：集成测试

```java
@SpringBootTest
@AutoConfigureMockMvc
class UserControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @Autowired
    private ObjectMapper objectMapper;

    @MockBean
    private UserService userService;

    @Test
    void shouldGetUser() throws Exception {
        User user = new User();
        user.setId(1);
        user.setName("John");

        when(userService.getUserById(1)).thenReturn(user);

        mockMvc.perform(get("/users/1"))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.name").value("John"));
    }
}
```

### 测试切片

Spring Boot 提供多种测试切片，只加载必要的组件：

```java
// 仅测试 Web 层
@WebMvcTest(UserController.class)
class UserControllerTest { }

// 仅测试数据层
@DataJpaTest
class UserRepositoryTest { }

// 仅测试 Service 层（需配合 @ExtendWith）
@ExtendWith(SpringExtension.class)
class UserServiceTest { }
```

## 七、Testcontainers

Testcontainers 是一个基于 Docker 的测试工具，用于在测试时创建临时的容器化环境。

### 核心优势

| 优势 | 说明 |
|------|------|
| **隔离性** | 每次测试使用全新的容器环境 |
| **一致性** | 开发、测试、生产环境一致 |
| **便捷性** | 无需本地安装中间件 |
| **可复用** | 可复用运行中的容器（配置 `reuse=true`） |

### 依赖引入

```xml
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>testcontainers</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>mysql</artifactId>
    <scope>test</scope>
</dependency>
```

### 基本用法

```java
@Testcontainers
@SpringBootTest
class BaseContainerTest {

    @Container
    static MySQLContainer<?> mysql = new MySQLContainer<>("mysql:8.0")
        .withDatabaseName("test_db")
        .withUsername("test")
        .withPassword("test")
        .withReuse(true); // 复用容器

    @DynamicPropertySource
    static void configureTestProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", mysql::getJdbcUrl);
        registry.add("spring.datasource.username", mysql::getUsername);
        registry.add("spring.datasource.password", mysql::getPassword);
    }
}
```

### 容器复用说明

配置 `withReuse(true)` 后，Testcontainers 会复用已运行的容器：

```java
// 仅复用「处于运行状态」的容器
.withReuse(true)
```

> ⚠️ **重要提示**：Testcontainers 的容器复用功能有一个硬性前提——**仅复用处于运行状态的容器**。已停止的容器会被框架判定为「不可用资源」，不会尝试重启或复用，而是直接新建。

### 测试类继承

所有集成测试可以继承基类，复用容器配置：

```java
class ViewQuestionsTest extends BaseContainerTest {
    // 自动使用基类中的 MySQL 容器
}
```

> 📖 官方文档：https://www.testcontainers.org/

## 八、MockMvc Web 层测试工具

MockMvc 是 Spring 提供的 Web 层测试工具，用于模拟 HTTP 请求。

### 基本用法

```java
@SpringBootTest
@AutoConfigureMockMvc
class QuestionControllerTest {

    @Autowired
    private MockMvc mockMvc;

    @Autowired
    private ObjectMapper objectMapper;

    @Test
    void shouldCreateQuestion() throws Exception {
        QuestionDto dto = new QuestionDto();
        dto.setTitle("如何学习 Spring Boot？");
        dto.setContent("求指导...");

        mockMvc.perform(post("/questions")
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(dto)))
            .andExpect(status().isOk())
            .andExpect(jsonPath("$.code").value(200))
            .andExpect(jsonPath("$.data.title").value("如何学习 Spring Boot？"));
    }
}
```

### 常用方法

| 方法 | 说明 |
|------|------|
| `perform()` | 执行请求 |
| `andExpect()` | 断言响应 |
| `andDo()` | 额外操作（如打印） |

### 请求构建

```java
// GET 请求
mockMvc.perform(get("/users/{id}", 1))

// POST 请求
mockMvc.perform(post("/users")
    .contentType(MediaType.APPLICATION_JSON)
    .content(json))

// PUT 请求
mockMvc.perform(put("/users/{id}", 1)
    .contentType(MediaType.APPLICATION_JSON)
    .content(json))

// DELETE 请求
mockMvc.perform(delete("/users/{id}", 1))

// 带请求头
mockMvc.perform(get("/users")
    .header("Authorization", "Bearer token"))

// 带查询参数
mockMvc.perform(get("/users")
    .param("page", "1")
    .param("size", "10"))
```

### 响应断言

```java
// 状态码断言
.andExpect(status().isOk())           // 200
.andExpect(status().isCreated())      // 201
.andExpect(status().isBadRequest())   // 400
.andExpect(status().isUnauthorized()) // 401
.andExpect(status().isNotFound())     // 404

// JSON 断言
.andExpect(jsonPath("$.code").value(200))
.andExpect(jsonPath("$.data.name").value("John"))
.andExpect(jsonPath("$.data").exists())
.andExpect(jsonPath("$.data").doesNotExist())

// 内容断言
.andExpect(content().contentType(MediaType.APPLICATION_JSON))
.andExpect(content().string("expected"))
```

### 打印请求和响应

```java
mockMvc.perform(get("/users"))
    .andDo(print())  // 打印完整的请求和响应
    .andExpect(status().isOk());
```

## 十、测试最佳实践

### 1. 测试命名规范

使用描述性的测试名称：

```java
// ❌ 不好的命名
@Test
void test1() { }

// ✅ 好的命名
@Test
@DisplayName("游客不能评论问题")
void guests_may_not_comment_a_question() { }

// ✅ 或使用中文描述
@Test
@DisplayName("已登录用户可以评论已发布的问题")
void signedInUserCanCommentPublishedQuestion() { }
```

### 2. 测试结构（AAA 模式）

```java
@Test
void shouldCreateUser() {
    // Arrange（准备）
    UserDto dto = new UserDto();
    dto.setName("John");
    
    // Act（执行）
    User result = userService.createUser(dto);
    
    // Assert（断言）
    assertThat(result.getName()).isEqualTo("John");
}
```
>注：由于笔者的习惯，本文档将使用 Given、When、Then 的 en、en、en 模式，不要见怪。
### 3. 测试数据清理

每个测试前清理数据，保证测试独立性：

```java
@BeforeEach
void setUp() {
    // 清空测试数据
    questionMapper.deleteByExample(null);
    answerMapper.deleteByExample(null);
}
```

### 4. 测试独立性

每个测试应该是独立的，不依赖其他测试的执行结果：

```java
// ❌ 不好的做法：测试之间有依赖
@Test
void test1() { /* 创建数据 */ }

@Test
void test2() { /* 依赖 test1 创建的数据 */ }

// ✅ 好的做法：每个测试独立
@Test
void shouldCreateData() {
    // 自己创建数据
}

@Test
void shouldQueryData() {
    // 自己也创建数据
}
```
