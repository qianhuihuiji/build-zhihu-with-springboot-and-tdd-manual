## 二、核心概念总结

### 2.1 AAA 测试模式

| 步骤 | 英文 | 说明 | 示例 |
|------|------|------|------|
| 准备 | Arrange | 设置测试环境和数据 | 创建测试用户 |
| 执行 | Act | 执行测试动作 | 发送 HTTP 请求 |
| 验证 | Assert | 验证预期结果 | 断言状态码 |

```java
@Test
void user_can_view_questions() throws Exception {
    // given (Arrange)
    Question question = new Question();
    question.setTitle("测试问题");
    questionMapper.insert(question);
    
    // when (Act)
    this.mockMvc.perform(get("/questions"))
    
    // then (Assert)
    .andExpect(status().isOk())
    .andExpect(jsonPath("$.data", hasSize(1)));
}
```

### 2.2 测试层次

| 层次 | 说明 | 工具 |
|------|------|------|
| **单元测试** | 测试单一组件 | JUnit + Mockito |
| **集成测试** | 测试组件协作 | Spring Boot Test + MockMvc |
| **端到端测试** | 测试完整流程 | Testcontainers |

### 2.3 测试命名规范

```java
// ✅ 推荐：下划线风格
@Test
void user_can_view_questions() { }

@Test
void guest_cannot_create_question() { }

// ❌ 不推荐：test 开头
@Test
void testUserCanViewQuestions() { }

@Test
void test1() { }  // 更糟糕
```

### 3.1 测试代码组织

```
src/test/java
└── com.nofirst.spring.tdd.zhihu.startup
    ├── BaseContainerTest.java       # 测试基类
    ├── integration                   # 集成测试
    │   ├── questions                 # 问题相关测试
    │   │   ├── ViewQuestionsTest.java
    │   │   └── CreateQuestionTest.java
    │   └── answers                   # 回答相关测试
    │       └── PostAnswerTest.java
    └── unit                          # 单元测试
        └── service                   # Service 层测试
            └── QuestionServiceTest.java
```

### 3.2 测试数据管理

```java
@BeforeEach
public void setUp() {
    // 1. 清理旧数据
    questionMapper.deleteByExample(null);
    
    // 2. 创建测试数据
    createTestData();
}

@AfterEach
public void tearDown() {
    // 3. 清理测试数据（可选）
    questionMapper.deleteByExample(null);
}
```

### 3.3 测试独立性

```java
// ✅ 好的做法：每个测试独立
@Test
void should_create_question() {
    // 自己创建数据
}

@Test
void should_query_question() {
    // 自己也创建数据
}

// ❌ 坏的做法：测试之间有依赖
@Test
void test1() { /* 创建数据 */ }

@Test
void test2() { /* 依赖 test1 的数据 */ }
```

### 3.4 测试覆盖范围

| 覆盖项 | 说明 | 示例 |
|--------|------|------|
| 正常流程 | 验证功能正常工作 | 用户可以查看问题 |
| 边界条件 | 验证边界情况 | 空列表、单条数据 |
| 异常情况 | 验证错误处理 | 未登录用户不能操作 |
| 权限验证 | 验证访问控制 | 游客不能创建问题 |

## 四、常用代码片段

### 4.1 测试类模板

```java
@TestInstance(TestInstance.Lifecycle.PER_CLASS)
public class MyTest extends BaseContainerTest {

    private MockMvc mockMvc;

    @Autowired
    private WebApplicationContext context;

    @Autowired
    private MyMapper myMapper;

    @BeforeAll
    public void setupMockMvc() {
        mockMvc = MockMvcBuilders
                .webAppContextSetup(context)
                .build();
    }

    @BeforeEach
    public void setUp() {
        // 清理并准备测试数据
        myMapper.deleteByExample(null);
    }

    @Test
    void should_do_something() throws Exception {
        // given
        
        // when
        this.mockMvc.perform(get("/api"))
        // then
                .andExpect(status().isOk());
    }
}
```

### 4.2 常用断言

```java
// 状态码断言
.andExpect(status().isOk())           // 200
.andExpect(status().isCreated())      // 201
.andExpect(status().isBadRequest())   // 400
.andExpect(status().isUnauthorized()) // 401
.andExpect(status().isNotFound())     // 404

// JSON 断言
.andExpect(jsonPath("$.code").value(200))
.andExpect(jsonPath("$.data").isArray())
.andExpect(jsonPath("$.data", hasSize(2)))
.andExpect(jsonPath("$.data[0].title").value("标题"))

// 打印请求
.andDo(print())
```

### 4.3 常用 Mock 操作

```java
// 定义 Mock 返回值
when(userService.getUserById(1)).thenReturn(mockUser);

// 定义 Mock 抛出异常
when(userService.getUserById(null))
    .thenThrow(new IllegalArgumentException("ID 不能为空"));

// 验证方法调用
verify(userService).getUserById(1);
verify(userService, times(2)).getUserById(1);
verify(userService, never()).getUserById(null);
```

## 五、常见问题

### Q: 测试运行很慢怎么办？

**A:** 
- 使用 Testcontainers 容器复用（`withReuse(true)`）
- 只运行相关测试（`-Dtest=MyTest`）
- 考虑使用单元测试代替部分集成测试

### Q: 测试数据如何隔离？

**A:** 
- 每个测试前清理数据（`@BeforeEach`）
- 使用事务回滚（`@Transactional`）
- 使用独立的测试数据库

### Q: 如何测试需要登录的接口？

**A:** 
- 使用 `@WithMockUser` 注解
- 使用 `@WithUserDetails` 注解
- 手动添加认证 Token

### Q: TDD 会不会降低开发速度？

**A:** 
- 短期内可能会稍慢（需要写测试）
- 长期来看会更快（减少 bug，便于重构）
- 代码质量更高，维护成本更低
