# 让测试通过

上一节中，我们创建并运行了第一个测试（虽然失败了）。这一节我们一起来编写代码，让测试通过。

---

## 一、问题分析

### 1.1 错误回顾

运行测试后，我们看到以下错误：

```
java.lang.AssertionError: Status expected:<200> but was:<404>
Expected :200
Actual   :404
```

### 1.2 错误分析

| 错误码 | 含义 | 原因 |
|--------|------|------|
| 404 | Not Found | 路由不存在，未创建对应的 Controller |

测试期望访问 `/questions` 接口返回 200，但实际返回 404，说明**路由不存在**。

---

## 二、创建 Controller

### 2.1 创建 QuestionController

创建文件 *src/main/java/com/nofirst/spring/tdd/zhihu/startup/controller/QuestionController.java*：

```java
package com.nofirst.spring.tdd.zhihu.startup.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class QuestionController {

    /**
     * 获取问题列表
     */
    @GetMapping("/questions")
    public void index() {
        // 暂时不实现任何逻辑
    }
}
```

### 2.2 代码解析

#### 类级别注解

| 注解 | 说明 |
|------|------|
| `@RestController` | 标记这是一个 REST 控制器，返回 JSON 数据（而非视图） |

#### 方法级别注解

| 注解 | 说明 |
|------|------|
| `@GetMapping("/questions")` | 映射 GET 请求到 `/questions` 路径 |

#### 方法返回值

```java
public void index() {
    // 空方法，暂时不返回任何数据
}
```

> 💡 **说明**：返回 `void` 时，Spring Boot 默认返回 200 OK 且响应体为空。这对于我们的第一个测试已经足够。

## 五、改进 Controller 返回值

虽然测试通过了，但返回空响应体并不友好。让我们改进一下，返回一个标准的响应格式。

### 5.1 修改 Controller

更新 *QuestionController.java*：

```java
package com.nofirst.spring.tdd.zhihu.startup.controller;

import com.nofirst.spring.tdd.zhihu.startup.common.CommonResult;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.Collections;
import java.util.List;

@RestController
public class QuestionController {

    /**
     * 获取问题列表
     */
    @GetMapping("/questions")
    public CommonResult<List<Object>> index() {
        // 返回空列表
        return CommonResult.success(Collections.emptyList());
    }
}
```

### 5.2 运行测试

再次运行测试，应该仍然通过：

```bash
mvn test -Dtest=ViewQuestionsTest
```

### 5.3 验证响应

现在访问 `/questions` 接口会返回：

```json
{
    "code": 200,
    "message": "操作成功",
    "data": []
}
```

## 七、总结

### 7.1 本节学习要点

| 要点 | 说明 |
|------|------|
| TDD 流程 | 测试 → 失败 → 实现 → 通过 |
| Controller 创建 | 使用 `@RestController` 和 `@GetMapping` |
| 最小实现原则 | 只编写使测试通过的最少代码 |
| 版本控制 | 及时提交代码，保持提交粒度小 |

### 7.2 TDD 核心思想

> 首先编写一个测试，运行这个测试看着它失败。然后编写最少量的代码取得一些进展，再运行测试。如此不断重复，直到测试通过为止。最后，或许还要重构代码，测试能确保不破坏任何功能。
